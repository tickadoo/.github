# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability and do not include live
credentials, personal data, payment data, or unnecessary production data in a
report.

Use tickadoo's private GitHub vulnerability-reporting channel:

[Report a vulnerability privately](https://github.com/tickadoo/.github/security/advisories/new)

Please include:

- the affected repository, service, route, or version;
- a concise impact assessment;
- safe reproduction steps or a minimal proof of concept;
- any conditions required for exploitation; and
- a suggested mitigation, if known.

Do not access, modify, download, or retain data that is not yours. Stop testing
once you have enough evidence to demonstrate the issue. Please allow the team a
reasonable opportunity to investigate and remediate before public disclosure.

## Supported versions

tickadoo prioritizes the versions currently deployed from supported default
branches. Older or archived versions may require an upgrade as part of a fix.
